PRV-16
# Photos for posts, and `<Gallery>`

**Planned:** Sonnet, M, wave 4

- **Goal:** putting photos in a post is one command, and no photo carrying metadata reaches a commit. The repo is
  public, so a pushed branch publishes a photo's location. Stripping before the commit is the control; PRV-1's
  hook and CI guard are backstops.
- **Depends on:** PRV-8 (`scripts/photos/core.ts`), PRV-10 (the shared Gallery component), PRV-14 (schema and
  post template).
- **Scope:**
  - **Files:** may touch only `scripts/photos/`, the `photos` script in `package.json`, `components/gallery/`, the
    MDX component registry, `content/blog/first-marathon.mdx`, `public/blog/first-marathon/`, the `SocialPost`
    component file (removed only if nothing else uses it), `e2e/fixtures/` (the fixture photo and post),
    `e2e/photos.spec.ts`, `lib/image-loader.ts` (limited to consuming the post variant manifest and keeping existing
    site-image selection), `e2e/guards.spec.ts` (limited to removing PRV-1's `marathon post embeds as links`
    scenario, which AC6 replaces), and `docs/boards/sections.json`, `docs/boards/merged.json`.
  - **`npm run photos -- <post-slug> <files…>`** (`scripts/photos/cli.ts`; the repo uses npm, not pnpm):
    - requires a single valid post slug other than `work` or `life` (nothing that escapes `public/blog/<slug>/`) and
      at least one input file, and rejects inputs that would generate the same output filenames;
    - accepts JPEG, PNG and WebP. A HEIC file is refused with a message to export it as JPEG first, because
      sharp's prebuilt binaries do not decode HEIC;
    - auto-orients, strips all metadata, and writes `public/blog/<slug>/<name>-{800,1600}.webp`, never wider than
      the original, plus a variant manifest under `public/blog/<slug>/` giving each variant's URL and actual encoded
      width;
    - reads originals in place and never copies them into the repo;
    - checks every output with `scripts/image-metadata.ts` before it exits;
    - prints a ready-to-paste `<Gallery>` with one `<Photo src width height alt="TODO: describe this photo" />`
      per file (with `caption="TODO: caption"`).
  - **`<Gallery>` (PRV-10's shared component) and `<Photo>`,** registered as MDX components. Props are strings, because
    `next-mdx-remote/rsc` strips expressions. `src`, `alt` and `caption` are required strings (the board draws a caption for every photo); `width` and `height`
    are required strings holding positive integer pixel dimensions. Invalid props fail the production build naming
    the post. Photos use PRV-8's loader, which reads the post variant manifest.
    The Gallery follows `pages-post-life-*` at both widths: one active photo at a time with its caption and an
    "n / N" counter, previous and next controls ("Previous photo", "Next photo", wrapping around), and a
    thumbnail row in which each thumbnail picks its photo and the active one is pressed. A pick crossfades
    (200 ms, ease; instant under reduced motion). Photos have the 14px radius.
  - **The marathon post (owner, 2026-11-20):** replace the marathon link card with a Gallery generated by
    `npm run photos`. Use the owner's race photos and captions when available and stand-ins until they arrive; the
    ticket ships with stand-in images through the same pipeline and never waits on the owner's photos (swapping
    them in is a later content-only follow-up, outside these ACs). Check the post against `pages-post-life-*`. The `SocialPost` import goes
    if nothing else uses it.
- **AC:**
  1. In a temporary directory, synthetic Exif, GPS, XMP and orientation 6 are added to a clean JPEG fixture; only
     clean fixture images are committed. The command runs on that JPEG and on PNG and WebP fixtures, including
     sources narrower than 800 px and between 800 and 1600 px. For every source, `<name>-800.webp` and
     `<name>-1600.webp` are written under `public/blog/<slug>/` with widths equal to the lesser of the requested
     width and the oriented source width. Include a source wider than 1600 px. Assert that the manifest lists the
     URL of every generated variant and that each recorded width equals the decoded width of that file. The JPEG comes out upright, every output passes
     `scripts/image-metadata.ts`, and the originals are unchanged and never copied into the repo. T:
     `photos.spec.ts › strips, orients, sizes`.
  2. The printed snippet contains one `<Photo>` per input, in input order, with quoted `src`, `width`, `height`,
     `alt` and `caption` attributes and both documented placeholders. With both placeholders filled in, the
     production build succeeds and each image uses its emitted URL and dimensions and shows its supplied caption
     when selected. For each photo, assert that the snippet's width and height match the decoded dimensions of its
     `src` file and that the rendered image exposes the alt text supplied in the snippet. T: `photos.spec.ts › snippet renders`.
  3. HEIC, the reserved slugs `work` and `life`, a path-like slug, no input files, an unreadable or unsupported

     exits non-zero, names the rejected file, prints no snippet and leaves no unverified output in `public/blog/`.
     In the temporary test workspace, try a traversal slug whose target would fall outside `public/blog/`. Assert
     that each invalid-slug case creates, changes or deletes no output file anywhere in the workspace.
     T: `photos.spec.ts › clear refusals`.
